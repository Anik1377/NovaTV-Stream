   103→--- [CRITICAL-03] Unauthenticated Supabase Setup Endpoint (DDL) ---
   104→File: /home/z/my-project/src/app/api/supabase/setup/route.ts, Lines 8-37
   105→Severity: CRITICAL
   106→Finding: `POST /api/supabase/setup` has zero authentication. Any unauthenticated user can hit this endpoint. While the current implementation only returns SQL (not executing it via the REST path shown), the endpoint still makes a fetch call to `${supabaseUrl}/rest/v1/rpc/exec_sql` using the PUBLISHABLE_KEY as both `apikey` and `Authorization: Bearer`.   1301→## 17. ADDITIONAL SECURITY OBSERVATIONS
  1302→
  1303→### Caddy SSRF via XTransformPort
  1304→The Caddyfile has a dangerous routing rule: if query param `XTransformPort` is present, it proxies to `localhost:{value}`. This effectively allows any external request to reach any service running on localhost.
  1305→
  1306→### Third-Party iframe Embeds
  1307→The app loads video content via iframes pointing to 10 third-party streaming services (vidsrc.cc, videasy.net, etc.). These iframes execute arbitrary JavaScript from untrusted domains — a significant XSS surface.
  1308→
  1309→### X-Frame-Options Conflict
  1310→The middleware sets X-Frame-Options: DENY globally, but the app relies on iframes for video playback. This either breaks video playback or the header is ignored by browsers for same-origin frames only.
